JSON을 이해하는 데 도움이 되는 이야기

JSON은 JavaScript Object Notation의 줄임말이지만, 지금은 특정 프로그래밍 언어에만 묶이지 않는 데이터 교환 형식으로 널리 사용됩니다. 사람이 읽기 쉬운 텍스트로 데이터를 표현하면서도 프로그램이 파싱하기 쉽다는 점이 장점입니다. 객체는 중괄호 안에 키와 값을 담고, 배열은 대괄호 안에 순서가 있는 값을 담습니다. 값에는 문자열, 숫자, 불리언, null, 객체, 배열이 올 수 있습니다.

JSON이 단순해 보이는 이유는 문법 규칙이 비교적 작기 때문입니다. 하지만 작은 기호 하나가 구조 전체를 바꿀 수 있습니다. 큰따옴표와 작은따옴표를 혼동하거나, 키에 따옴표를 빠뜨리거나, 배열과 객체의 괄호를 서로 바꾸면 파싱이 실패합니다. 마지막 항목 뒤에 쉼표를 두는 습관도 JavaScript 객체 표기에서는 허용될 수 있지만 표준 JSON에서는 문제가 됩니다. 오류 위치가 파일 끝으로 표시되더라도 실제 원인은 그보다 앞선 괄호나 쉼표일 때가 많습니다.

보기 좋게 정렬하는 작업은 단순한 꾸미기가 아니라 디버깅 과정이기도 합니다. 들여쓰기를 적용하면 중첩된 객체의 범위와 배열의 길이, 예상치 못한 null 값이 눈에 들어옵니다. 반대로 전송 직전에는 공백과 줄바꿈을 줄인 압축 형식이 파일 크기를 낮추는 데 도움이 됩니다. 다만 압축은 내용을 검증하거나 잘못된 데이터를 고쳐 주는 기능이 아니므로, 먼저 유효성을 확인한 뒤 사용해야 합니다. 데이터베이스나 로그에서 복사한 문자열이 JSON 안에 다시 문자열로 들어 있는 경우에는 바깥쪽 따옴표를 한 겹씩 확인하면 구조를 훨씬 쉽게 파악할 수 있습니다.

데이터를 안전하게 다루는 작은 습관

JSON을 공유하기 전에는 개인정보와 비밀값을 먼저 확인하는 것이 중요합니다. 이메일 주소, 전화번호, 토큰, 쿠키, 내부 서버 주소, 테스트 계정 비밀번호가 객체 안에 섞여 있을 수 있습니다. 보기 좋게 정리하면 이런 값이 더 눈에 잘 띄므로 파싱 결과를 그대로 공개 저장소나 게시판에 올리기 전에 민감한 항목을 지우거나 가려야 합니다. JSON 파서는 구조를 보여주는 도구이지 민감한 내용을 자동으로 익명화하는 도구는 아닙니다. 개발 중에는 실제 서비스 키 대신 예시 값을 사용하고, 오류 재현에 필요한 필드만 남기는 습관을 들이면 협업과 보안을 함께 지킬 수 있습니다.
